# 09 · 答辩讲解提纲（项目总负责人视角）

> 用途：明天答辩前快速过一遍，把“负责什么”讲成“为什么这么设计、怎么做到的、效果如何”。
> 配合演示：README（GitHub 首页）+ 本地四端 + docs/ 文档。

## 0. 一句话讲清项目

**“一套共享后端 + 一个 MySQL 数据库，支撑四个角色化前端，跑通‘公众发现问题 → 网格员现场检测(AQI) → 监管处置 → 大屏决策’的完整环境治理闭环。”**

## 1. 项目总体架构（必讲）

### 1.1 为什么是“一后端四前端”？
- 数据同源：四端读写同一 MySQL（17 表），避免多套系统数据割裂；
- 角色差异大：公众要简单、监管要高密度、网格员要移动化、大屏要可视化 → 四个独立 Vue 应用各自优化体验；
- 复用最大化：全部业务/鉴权/状态机收口在共享后端，前端只做展示与交互。

```text
NEPS(5174) NEPM(5175) NEPG(5176) NEPV(5173)   ← 四个 Vue3 前端
      │  HTTP /api           │ WS /ws/notify
      ▼                      ▼
Spring Boot 共享后端 :8080（ctrl→service→dao）
      ▼ JDBC
MySQL 8 · nep · 17 表 · 18 外键
```

### 1.2 后端分层与职责
- Controller：只做参数接收与身份头读取，不写业务（业务域 Controller 零 DAO 注入）；
- Service：**状态机、权限归属、事务、通知触发**全部在 Service 收敛；
- DAO：MyBatis-Plus BaseMapper（17 个），无手写 SQL 侵入业务。

## 2. 数据库设计（可讲 1-2 分钟）

### 2.1 17 张表 = 5 组
| 组 | 表 | 作用 |
|---|---|---|
| 认证 | admins / users | 管理员（监管/大屏登录）与用户（公众+网格员） |
| 基础 | regions / devices / sensors | 区域树、设备点位、指标字典（驱动新增指标零代码） |
| 监测 | monitor_data / alerts / thresholds / data_quality | 时序数据、两级告警、阈值、质量/异常检测 |
| 监督业务 | supervision_event / attachment / event_status_log / event_evaluation | 事件主体、图片、**全状态审计日志**、评价 |
| 网格任务 | grids / grid_member / inspection_task / inspection_record | 网格、成员、任务、六项检测+AQI |

### 2.2 三个设计亮点（答辩加分点）
1. **event_status_log 审计链**：状态机每一步都落一条日志（创建→审核→派单→接单→开始→提交→核实→关闭 = 8 条），三端都能看到同一时间线 → 责任可追溯；
2. **最小迁移原则**：业务演进只加表/加可空列（migration_v4 网格监督 8 表、v5 优先级/停用、v6 检测六项+AQI），从不删改既有结构与数据 → 历史系统零破坏；
3. **检测数据独立成表**（inspection_record 六项+AQI+坐标+照片）而非塞进 monitor_data —— 现场检测与设备采集两种数据语义分离。

## 3. NEPV 决策可视化大屏（你独立完成，重点讲）

- 定位：决策驾驶舱（不是管理后台）——一屏看“环境质量 + 监管态势”；
- 深色驾驶舱设计语言：Floating HUD 悬浮导航、Hero 首屏 AQI、滚动叙事动画、ECharts 仪表盘/实时曲线/空间分布/告警趋势；
- 数据链路：WebSocket 实时数据（data/alert，5s 模拟上报推送）+ 30s 轮询兜底 + `/stats/overview|supervision` 统计聚合；
- 亮点：新增 **05 REGULATION 监管区块** —— 把业务数据（监督事件/任务完成率/高风险/区域分布）从“设备监测”拓展到“业务监管”一屏通览；
- 数据真实性：大屏全部数字来自真实 API（业务表聚合），无任何写死/Mock。

## 4. 四端 API 接口设计与联调（重点讲）

### 4.1 接口契约
- 统一前缀 /api、统一响应 {code,message,data}、分页 {total,pages,records}、时间 ISO 格式；
- **Long ID 字符串化**（Jackson ToStringSerializer）：alerts/事件/任务/记录 id 防前端 JS 精度丢失（2^53 问题）——答辩细节加分；
- 身份：X-User-Id（公众/网格员）/ X-Admin-Id（管理员）+ Authorization Bearer token（登录签发、24h 过期、登出失效、乱 token 401——后来加的令牌校验）。

### 4.2 端到端联调（实测过）
```text
NEPS 提交(PENDING_REVIEW) → NEPM admin/list 立即可见
→ NEPM 审核(APPROVED)/派单 → inspection_task 创建(event_id 关联) → NEPG mine 立即可见(ASSIGNED)
→ NEPG 接单(ACCEPTED)→开始(INSPECTING)→提交六项检测(INSPECTED, AQI 后端计算入库)
→ NEPM records 查看检测结果 → 核实(VERIFIED)→关闭(CLOSED, 事件任务同步)
→ NEPS 详情 8 条时间线 + “已处理” → NEPV 统计实时变化
```
ID 全链一致（user→event→task→record→log），动态测试验证零断链。

### 4.3 WebSocket 联调（讲设计）
- 单端点 /ws/notify（复用，不另起一套）；连接带身份 query（role=ADMIN|GRID|PUBLIC&id）；
- 全量广播保留给大屏实时数据；**业务通知定向发送**：SUPERVISION_CREATED→管理员、TASK_ASSIGNED→被派网格员、TASK_ACCEPTED/DETECT_SUBMITTED→管理员、EVENT_CLOSED→提交人；
- 原则：WebSocket 只做提醒，数据永远以 REST+DB 为准（断线重连 3s，重连后自行拉取）。

## 5. 系统测试与 Bug 修复（讲方法论）

- 自动化：后端 76 个用例（13 个测试类）全绿：状态机顺序/重复操作/越权矩阵/不存在 ID/时间线完整性/统计联动/事务回滚；
- 动态审计：16 场景越权全拒、状态注入（前端传 status=CLOSED）被后端强制；
- 实际修过的代表性 Bug（讲 2-3 个即可）：
  1. **登录后黑屏** = Vue setup 漏 import onUnmounted（构建不报、运行才炸）→ 补 import；
  2. **任务域无事务**：提交检测跨 4 张表，中途异常会部分提交 → 补 @Transactional + 回滚测试；
  3. **图片上传缺失**：只登记文件名 → 新增 /api/upload + 存储 + 静态映射 + 前端先传后展示；
  4. **异常泄露**：兜底返回 e.getMessage() → 固定文案脱敏。

## 6. 答辩高频问题速答

| 可能被问 | 怎么答（一句要点） |
|---|---|
| 为什么四个端共用后端？ | 数据同源、状态机与权限单点控制；前端按角色体验独立 |
| AQI 怎么算的？ | HJ633-2012 六污染物 1 小时均值分段线性插值，取最大 IAQI；缺项不参与；后端权威计算+前端实时预览 |
| 状态机在哪里控制？前端能不能乱传状态？ | Service 内方法级流转（approve/assign/accept…），DTO 无 status 字段+Service 强设，实测注入被拒 |
| 权限怎么做的？ | 身份头 + 归属校验：事件按 user_id、任务按 assignee_id，越权 401/403 + 令牌校验 |
| 事务一致性怎么保证？ | 关键写链路 @Transactional：派单/检测提交/核实关闭跨表同滚同成，回滚测试验证 |
| 数据实时性？ | 模拟器 5s/轮 → WS data 广播 → 大屏秒级刷新；业务变化走定向通知+前端 API 拉取兜底 |
| 有 Mock 吗？ | 没有；统计/业务全真实（监测数据由场景模拟器产生，接硬件可关模拟器走上报接口） |
| 数据库迁移怎么演进？ | 只增不改删：v2 告警生命周期+质量表、v3 设备坐标、v4 网格监督 8 表、v5 优先级/停用、v6 检测六项 |
| 告警/事件 ID 为什么是字符串？ | 雪花 bigint 超 JS 安全整数，ToStringSerializer 防精度丢失 |
| 你负责的部分是什么？ | 总体架构/前后端架构/数据库设计/NEPV 大屏/四端接口与 WS 联调/测试与缺陷修复/验收 |
