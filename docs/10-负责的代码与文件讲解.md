### 联调核心：`service/impl/SupervisionEventServiceImpl.java`（背熟这个方法表）
| 方法 | 状态流转 | 附带动作 |
|---|---|---|
| create | →PENDING_REVIEW | 附件登记 + 状态日志 + WS 通知管理员 + @Transactional |
| approve/reject | PENDING_REVIEW→APPROVED/REJECTED | 日志（管理员写 remark） |
| assign | APPROVED→ASSIGNED | 校验网格/网格员/优先级白名单 → **创建 inspection_task** + 日志 + WS 通知网格员 |
| detail | - | 归属校验（本人或管理员）+ 返回 taskId/taskNo |

### `InspectionTaskServiceImpl.java`（网格员侧状态机，注意 6 个 @Transactional）
| 方法 | 流转 | 附带动作 |
|---|---|---|
| accept/start | ASSIGNED→ACCEPTED→INSPECTING | 任务+事件同步 + 日志 + WS 通知管理员(接单) |
| submit | INSPECTING→INSPECTED | **写检测记录（六项+AQI 计算）+ 任务/事件同步 + 日志 + WS 通知管理员(含 AQI)** |
| verify/close | INSPECTED→VERIFIED→CLOSED | 事件同步 + 日志 + close 时 WS 通知公众“已处理完成” |
| calcAQI | 静态 | HJ633-2012 六污染物分段线性插值取最大 IAQI（可现场演示：88.5→117） |

## 职责六：WebSocket 联调 → `ws/NotifyWebSocketHandler.java`

- **复用单端点** /ws/notify（不另起一套），连接 query 身份：role=ADMIN|GRID|PUBLIC&id；
- broadcast()：全量广播（NEPV data/alert 实时链路，向后兼容）；
- sendNotifyToAdmins / sendNotifyToUser：定向业务通知；消息由 Jackson 序列化（防手拼转义）；
- 5 类事件与触发点（背）：SUPERVISION_CREATED(create)/TASK_ASSIGNED(assign)/TASK_ACCEPTED(accept)/DETECT_SUBMITTED(submit,含AQI)/EVENT_CLOSED(close)；
- 原则句：**“WebSocket 只做提醒，数据以 REST+MySQL 为准”**——断线重连后前端自行拉取。

## 答辩“文件指路”话术示例

- “状态机在这——`SupervisionEventServiceImpl.approve()/assign()` 与 `InspectionTaskServiceImpl.accept()/submit()/verify()/close()`，每步都校验前置状态、写 event_status_log、同步事件任务双表。”
- “审计在这——关闭后查 `event_status_log`，正好 8 条：PENDING_REVIEW>APPROVED>ASSIGNED>ACCEPTED>INSPECTING>INSPECTED>VERIFIED>CLOSED。”
- “AQI 在这——`InspectionTaskServiceImpl.calcAQI()`，六项分别插值取最大，缺项不参与。”
- “通知在这——`NotifyWebSocketHandler` 按身份定向发送，触发点都在 Service 状态流转方法里。”
- “大屏实时在这——`Dashboard.vue` 的 onWSMessage 收到 data 就更新仪表与曲线；统计走 `/stats/overview|supervision`。”
