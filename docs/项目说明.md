# 项目说明

> 基于 Spring Boot 与 Vue 的多合一环境监测保护系统 —— 设计与实现文档

## 一、项目背景与意义

随着工业化与城市化进程加快，空气污染、水质恶化、噪声扰民等环境问题日益突出。传统环境监测依赖人工巡检与专业仪器，成本高、时效差。本项目设计并实现一套**多合一环境监测保护系统**，覆盖空气质量（PM2.5/CO2/温湿度）、水质（pH/浊度/溶解氧）与噪声三类指标，实现环境数据的**自动采集、实时展示、阈值告警**闭环管理，为校园/园区环境管理提供低成本、可扩展的监测方案。

## 二、需求分析

### 2.1 功能需求
- 设备管理：监测设备/站点的增删改查、类型与状态管理
- 数据采集：模拟器自动上报 + 预留真实硬件（HTTP/MQTT）接入
- 数据展示：实时监测大屏（仪表盘、实时曲线、空间分布）、历史数据查询与趋势分析
- 告警管理：阈值预警/报警两级告警、30 分钟防重复、处理闭环
- 系统管理：管理员登录、用户管理、阈值配置

### 2.2 非功能需求
- 数据上报事务一致性（数据+设备状态+告警同事务）
- 实时性（WebSocket 推送，秒级到达）
- 界面友好（ENVISION 深色驾驶舱设计语言）
- 可扩展性（指标字典驱动、设备类型可扩展）

## 三、系统设计

### 3.1 总体架构
三层架构：数据源层（模拟器/硬件）→ 后端服务层（Spring Boot REST API + 阈值引擎 + WebSocket）→ 展示层（Vue3 前端）。数据层使用 MySQL 存储（8 张表：管理员/用户/区域/设备/指标字典/监测数据/阈值/告警）。

### 3.2 关键设计
1. **统一响应与异常处理**：Result<T> 封装 + 全局异常处理器，前后端契约清晰。
2. **指标字典驱动**：sensors 表登记指标编码/单位/标准限值，新增监测类型零代码扩展。
3. **两级阈值告警**：WARN（预警）/ ALARM（报警），设备级阈值优先全局默认；30 分钟防重复避免告警风暴。
4. **事务数据上报**：@Transactional 保证监测数据写入、设备状态更新、告警生成三者原子性。
5. **WebSocket 实时推送**：数据上报与告警产生即时广播，前端免轮询实时刷新。
6. **模拟器设计**：@Scheduled 定时任务按设备类型生成符合量程的随机数据（5% 概率产生峰值以演示告警），simulator.enabled 开关控制，接硬件时关闭。

## 四、核心功能实现

### 4.1 数据上报流程（核心事务）
```
POST /api/data/report
  ├─ 校验设备存在（device_code）
  ├─ 写入 monitor_data（逐指标）
  ├─ 更新设备 last_report_time + 在线状态
  ├─ 阈值校验（设备级→全局）→ 生成 WARN/ALARM 告警
  └─ WebSocket 广播（data / alert）
```

### 4.2 环境质量评分
参照 AQI 思想：`得分 = 指标值 / 标准限值 × 100`，>100 判定超标；综合得分为各指标均值。前端超标红色高亮。

### 4.3 实时大屏（ENVISION 驾驶舱）
深色主题（#0A0D0C 底 + 层级背景），Floating HUD 漂浮导航，Hero 首屏 + AQI 主指标，ECharts Gauge 仪表盘 + 平滑实时曲线 + 传感器空间分布图，WebSocket 驱动秒级更新，30 秒兜底轮询。

## 六、总结与展望

系统实现了环境监测从采集、存储、展示到告警的完整闭环，前后端分离、分层清晰、具备演示效果与扩展能力。展望：接入真实硬件（MQTT）、增加移动端、引入时序数据库（InfluxDB/TDengine）支撑更大数据量、基于历史数据的环境预测模型。
